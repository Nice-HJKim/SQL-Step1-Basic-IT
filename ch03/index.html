3.1 · 조건에 맞는 행 선택

필요한 데이터만 골라내기

필요한 고객·계좌·거래를 조건으로 고르고, 원하는 순서로 조회하기.

이 장의 목표
자료형 확인 → 조건 조합 → NULL·경계값 검증 → 결과 정렬

기본 문법

SELECT 컬럼명
FROM 테이블명
WHERE 조건;

WHERE절

  • 조건에 맞는 행 선택.
  • WHERE는 FROM 다음에 작성.

• 조건 없이 고객 목록 조회

SELECT customer_id, customer_name, customer_grade, branch_id
  FROM customers;

• 102번 영업점 고객 조회

SELECT customer_id, customer_name, customer_grade, branch_id
  FROM customers
 WHERE branch_id = 102;
✓ 조건에 맞는 행만 조회하며 원본 데이터는 바뀌지 않음.
✓ 결과가 0건이어도 SQL 오류가 아닐 수 있음.
조건을 작성하기 전에
✓ 대상 테이블과 출력 컬럼 확인.
✓ 포함할 값과 제외할 값 구분.
✓ NULL 포함 여부와 날짜·금액 경계 확인.
✓ 정렬 기준이 같은 행의 추가 순서 지정.
3.2 · 숫자와 문자 비교

숫자와 문자 비교

기본 문법

WHERE 컬럼명 = 값
WHERE 컬럼명 > 값
WHERE 컬럼명 <= 값
연산자의미
=같음
<>, !=, ^=같지 않음
>초과
>=이상
<미만
<=이하

• 이름이 김민준인 고객 조회

SELECT customer_id, customer_name, customer_grade, branch_id
  FROM customers
 WHERE customer_name = '김민준';
이름이 같아도 서로 다른 고객일 수 있음. 고객번호로 구분.

• 신용점수 600점 이하 고객 조회

SELECT customer_name, credit_score
  FROM customers
 WHERE credit_score <= 600;
✓ 문자값은 작은따옴표로 감싸기.
✓ 숫자는 쉼표 없이 작성. (예: 50000000)
컬럼 자료형에 맞게 비교
숫자 컬럼에는 숫자값, 문자 컬럼에는 작은따옴표로 감싼 문자값 사용.
날짜 컬럼에는 날짜값 사용. 화면에 보이는 모양보다 DESC로 자료형을 먼저 확인.

• 숫자 컬럼에 숫자값으로 조건 지정

SELECT customer_id, customer_name, branch_id
  FROM customers
 WHERE branch_id = 102;
암시적 형 변환에 의존하지 않기

branch_id = '102'도 자동 변환으로 실행될 수 있음. 실행 성공이 자료형을 적절히 맞췄다는 뜻은 아님. 숫자 컬럼에는 branch_id = 102로 작성.

날짜 문자열의 자동 변환은 세션의 날짜 형식에 영향을 받을 수 있음. 명시적 날짜 작성법은 3.11에서 학습.

3.3 · 범위로 조회하기

범위로 조회하기

기본 문법

WHERE 컬럼명 BETWEEN 시작값 AND 끝값

• 신용점수 700~800점 고객 조회

SELECT customer_name, credit_score
  FROM customers
 WHERE credit_score BETWEEN 700 AND 800;
700 이상, 800 이하를 의미함. 양 끝값도 포함.
같은 조건을 비교 연산자로 표현
WHERE credit_score >= 700
  AND credit_score <= 800
경계값 확인
700 이상: >= 700 · 700 초과: > 700
800 이하: <= 800 · 800 미만: < 800
실행 결과에 경계값이 없더라도 두 조건의 의미가 같은 것은 아님.
3.4 · 여러 값 중에서 고르기

여러 값 중에서 고르기

기본 문법

WHERE 컬럼명 IN (값1, 값2, 값3)

• 101·102·103번 영업점 고객 조회

SELECT customer_id, customer_name, credit_score, branch_id
  FROM customers
 WHERE branch_id IN (101, 102, 103);
✓ 목록 중 하나와 같으면 선택.
✓ 숫자는 그대로, 문자값은 작은따옴표로 감싸기.
같은 컬럼의 OR 조건을 IN으로 정리
WHERE branch_id = 101
   OR branch_id = 102
   OR branch_id = 103

-- 같은 의미
WHERE branch_id IN (101, 102, 103)

서로 다른 컬럼의 조건을 하나의 IN 목록으로 바꾸지는 않음.

3.5 · 문자 일부로 찾기

문자 일부로 찾기

기본 문법

WHERE 컬럼명 LIKE '문자 패턴'
  • %: 0개 이상의 문자.
  • _: 정확히 한 문자.

• 고객 이름이 김으로 시작하는 고객 조회

SELECT customer_name
  FROM customers
 WHERE customer_name LIKE '김%';

• 이름의 두 번째 글자가 ‘민’인 고객 조회

SELECT customer_name
  FROM customers
 WHERE customer_name LIKE '_민%';
'김%'는 김으로 시작하는 이름.
'_민%'는 두 번째 글자가 민인 이름.
문자 %와 _ 자체를 찾으려면

LIKE에서 %와 _는 패턴 기호. 문자 자체를 검색하려면 ESCAPE로 구분.

-- 이메일에 밑줄(_)이 들어간 고객을 찾는 조건
WHERE email LIKE '%!_%' ESCAPE '!'

!_는 밑줄 문자 한 개를 뜻함. 현재 실습 데이터에 해당 문자가 없으면 결과는 0건일 수 있음.

3.6 · 값이 없는 데이터 확인

값이 없는 데이터 확인

기본 문법

WHERE 컬럼명 IS NULL
WHERE 컬럼명 IS NOT NULL
NULL은 값이 없거나 확인되지 않은 상태. 0이나 공백과 다름.

• 영업점코드가 등록되지 않은 고객 조회

SELECT customer_name, branch_id
  FROM customers
 WHERE branch_id IS NULL;
✓ 영업점코드가 NULL이라는 사실만으로 온라인 가입 고객이라고 판단할 수 없음.

• 연락처가 등록된 고객 조회

SELECT customer_name, phone_number
  FROM customers
 WHERE phone_number IS NOT NULL;
NULL 비교 시 주의
  • = NULL, <> NULL 대신 IS NULL, IS NOT NULL 사용.
  • Oracle에서 빈 문자열('')은 NULL로 취급하지만, 공백 한 칸(' ')은 문자값임.
WHERE는 TRUE인 행만 선택
NULL과 일반 비교 연산자로 비교하면 TRUE/FALSE가 아닌 UNKNOWN.
FALSE와 UNKNOWN은 WHERE 결과에 포함되지 않음.
예: branch_id가 NULL이면 branch_id = 102와 branch_id <> 102 모두 UNKNOWN.

• 102번 영업점 제외 · 미등록 고객은 포함되지 않음

SELECT customer_id, customer_name, branch_id
  FROM customers
 WHERE branch_id <> 102
 ORDER BY customer_id;

• 102번 영업점 제외 · 미등록 고객도 포함

SELECT customer_id, customer_name, branch_id
  FROM customers
 WHERE branch_id <> 102
    OR branch_id IS NULL
 ORDER BY customer_id;
미등록 고객 10명 포함 여부에 따라 결과가 달라짐. “특정 영업점 제외”라는 요청만으로 NULL 처리 기준을 추측하지 않기.
3.7 · 여러 조건 함께 사용

여러 조건 함께 사용

기본 문법

WHERE 조건1 AND 조건2
WHERE 조건1 OR 조건2
  • AND: 두 조건을 모두 만족하는 행.
  • OR: 두 조건 중 하나 이상을 만족하는 행.

• 102번 영업점이면서 신용점수 800점 이상인 고객

SELECT customer_id, customer_name, branch_id, credit_score
  FROM customers
 WHERE branch_id = 102
   AND credit_score >= 800;

• 102번 영업점이거나 신용점수 800점 이상인 고객

SELECT customer_id, customer_name, branch_id, credit_score
  FROM customers
 WHERE branch_id = 102
    OR credit_score >= 800;
OR에서 두 조건을 모두 만족해도 같은 원본 행이 두 번 출력되지는 않음.
3.8 · 조건에서 제외하기

조건에서 제외하기

기본 문법

WHERE 컬럼명 NOT IN (값1, 값2)
WHERE 컬럼명 NOT BETWEEN 시작값 AND 끝값
WHERE 컬럼명 NOT LIKE '문자 패턴'

• BRONZE·NORMAL 등급을 제외한 고객 조회

SELECT customer_name, customer_grade
  FROM customers
 WHERE customer_grade NOT IN ('BRONZE', 'NORMAL');
NOT BETWEEN · NOT LIKE

• 신용점수 600~800점 범위를 벗어난 고객 조회

SELECT customer_name, credit_score
  FROM customers
 WHERE credit_score NOT BETWEEN 600 AND 800;
600~800점을 제외하면 600점 미만 또는 800점 초과.

• 고객 이름이 김으로 시작하지 않는 고객 조회

SELECT customer_name
  FROM customers
 WHERE customer_name NOT LIKE '김%';

• NOT IN 목록에 NULL이 포함된 경우

SELECT customer_id, customer_name, branch_id
  FROM customers
 WHERE branch_id NOT IN (101, 102, NULL);
이 조건으로 선택되는 행은 없음.
NOT IN (101, 102, NULL)은 각 값과 다르다는 조건을 AND로 연결한 의미.
NULL과의 비교가 UNKNOWN이므로 전체 조건이 TRUE가 될 수 없음.
미등록 고객을 제외하려면 IS NOT NULL, 포함하려면 OR branch_id IS NULL로 의도를 표현.
3.9 · 괄호로 조건 묶기

괄호로 조건 묶기

업무 요청
보통예금 또는 정기예금 중 잔액이 1천만원을 초과하는 계좌 조회.

기본 문법

WHERE (조건1 OR 조건2)
  AND 조건3

• 괄호 없이 작성한 조건과 결과 비교

SELECT account_number, account_type, balance
  FROM accounts
 WHERE account_type = '보통예금'
    OR account_type = '정기예금'
   AND balance > 10000000
ORDER BY balance, account_number;
AND가 OR보다 먼저 적용됨. 위 SQL은 보통예금을 잔액과 관계없이 포함.

• 괄호로 업무 의도를 명확하게 표현

SELECT account_number, account_type, balance
  FROM accounts
 WHERE (account_type = '보통예금'
    OR account_type = '정기예금')
   AND balance > 10000000
ORDER BY balance, account_number;
IN으로 간결하게 표현
WHERE account_type IN ('보통예금', '정기예금')
  AND balance > 10000000
조건 우선순위와 실행 순서 구분
AND는 OR보다 우선하여 논리적 의미를 결정. 괄호로 업무 의도를 명시.
WHERE에 적은 조건의 위아래 순서가 실제 평가 순서를 보장하지 않음. 물리적 처리 방식은 옵티마이저가 결정.
3.10 · 원하는 순서로 정렬

원하는 순서로 정렬

기본 문법

SELECT 컬럼명
FROM 테이블명
WHERE 조건
ORDER BY 정렬컬럼 ASC 또는 DESC;
  • ASC: 오름차순. 생략하면 기본 적용.
  • DESC: 내림차순.
  • ORDER BY가 없으면 결과 행의 순서를 보장하지 않음.
  • 여러 기준은 쉼표로 구분. 앞 기준이 같은 행끼리 다음 기준 적용.

• 잔액 오름차순 정렬

SELECT account_number, account_type, balance
  FROM accounts
ORDER BY balance ASC, account_number ASC;

• 생년월일 내림차순 정렬

SELECT customer_id, customer_name, customer_grade, birth_date
  FROM customers
ORDER BY birth_date DESC, customer_id ASC;
생년월일 내림차순은 최근 생년월일부터, 즉 나이가 어린 고객부터 표시.

• 결과 별칭으로 정렬

SELECT account_number, balance / 10000 AS "잔액(만원)"
  FROM accounts
ORDER BY "잔액(만원)" DESC, account_number ASC;
결과 별칭은 ORDER BY에서 사용 가능. 같은 SELECT문의 WHERE에서는 사용할 수 없음.

• 영업점별 신용점수 내림차순 정렬

SELECT customer_id, customer_name, branch_id, credit_score
  FROM customers
ORDER BY branch_id ASC NULLS LAST,
         credit_score DESC,
         customer_id ASC;
NULL의 정렬 위치
  • Oracle 기본값: ASC는 NULLS LAST, DESC는 NULLS FIRST.
  • NULLS FIRST: NULL을 앞에, NULLS LAST: 뒤에 표시.

• 영업점 미등록 고객을 먼저 표시

SELECT customer_id, customer_name, branch_id
  FROM customers
ORDER BY branch_id ASC NULLS FIRST, customer_id ASC;
DESC의 두 가지 사용 위치
  • DESC customers: 테이블 구조 확인. DESCRIBE의 줄임말.
  • ORDER BY balance DESC: 잔액 내림차순 정렬.
컬럼 위치 순번(Position)을 사용한 정렬
SELECT customer_id, customer_name, branch_id
  FROM customers
ORDER BY 3, 1 DESC;
  • 컬럼 순서 변경에 영향을 받으므로 컬럼명 사용 권장.

• 신용점수 내림차순 · 동점이면 고객번호 오름차순

SELECT customer_id, customer_name, credit_score
  FROM customers
 ORDER BY credit_score DESC NULLS LAST,
          customer_id ASC;
같은 점수의 고객도 순서가 명확하도록
credit_score만 지정하면 동점 고객 사이의 순서는 보장되지 않음.
고유한 customer_id를 다음 기준으로 지정. NULL 점수는 마지막에 표시.
정렬 기준 추가는 출력 순서를 명확히 하는 목적이며 성능 개선을 보장하지 않음.
3.11 · 날짜 범위로 조회

날짜 범위로 조회

기본 문법

WHERE 날짜컬럼 >= 기간_시작값
  AND 날짜컬럼 <  다음_기간_시작값
날짜에도 시간이 포함됨
Oracle DATE: 연·월·일·시·분·초.
TIMESTAMP: 소수 초까지 표현 가능.
현재 opened_date는 DATE, transaction_date는 TIMESTAMP. 화면에서 시간이 생략되어도 실제 값에 시간이 없다고 단정하지 않기.

• 종료일 조건 비교

-- 1월 31일 00:00까지만 포함하는 조건
WHERE transaction_date
      BETWEEN DATE '2026-01-01' AND DATE '2026-01-31'

-- 1월 전체를 포함하는 조건
WHERE transaction_date >= TIMESTAMP '2026-01-01 00:00:00'
  AND transaction_date <  TIMESTAMP '2026-02-01 00:00:00'
BETWEEN은 양 끝값을 포함하지만, 위 종료값은 1월 31일의 시작 시각.
1월 31일 00:00 이후 거래까지 포함하려면 다음 달 시작 미만으로 지정.
23:59:59를 끝값으로 지정하면 소수 초가 있는 값은 누락될 수 있음.

• 2026년 1월 거래 전체 조회

SELECT transaction_id, account_number, transaction_date,
       transaction_type, amount
  FROM transactions
 WHERE transaction_date >= TIMESTAMP '2026-01-01 00:00:00'
   AND transaction_date <  TIMESTAMP '2026-02-01 00:00:00';
DATE 컬럼의 연간 범위 조건
WHERE opened_date >= DATE '2022-01-01'
  AND opened_date <  DATE '2023-01-01'

함수로 컬럼을 문자로 바꾸지 않고 날짜값 자체를 비교. 날짜 표시 형식과 변환 함수는 다음 단원에서 학습.

3.12 · 실습 문제

실습 문제

문제와 결과 예시를 보고 SQL을 작성하세요. NULL 포함 여부·경계값·정렬 기준까지 확인하세요.

실습 1. 계좌 조회 조건 검증

보통예금 또는 정기예금 중 잔액이 1천만원을 초과하는 계좌의 계좌번호·계좌종류·잔액을 조회하세요. 잔액 오름차순, 잔액이 같으면 계좌번호 오름차순으로 정렬하세요.

실습 2. 영업점 제외와 미등록 고객

102번 영업점 고객을 제외하되 영업점코드가 등록되지 않은 고객은 포함하세요. 고객번호·고객명·영업점코드를 조회하고 고객번호 오름차순으로 정렬하세요.

실습 3. 월간 거래 조회

2026년 1월의 거래를 시간까지 빠짐없이 조회하세요. 거래번호·계좌번호·거래일시·거래유형·금액 순서로 출력하세요. 정렬은 지정하지 않습니다.

실습 4. 신용점수순 고객 목록

실습 5. 실행되지만 의도와 다른 조건 수정

다음 조건을 실습 1의 요구사항에 맞게 수정하세요. 수정 전 조건에서 잔액이 1천만원 이하인 보통예금이 포함되는 이유도 설명하세요.

SELECT account_number, account_type, balance
  FROM accounts
 WHERE account_type = '보통예금'
    OR account_type = '정기예금'
   AND balance > 10000000
 ORDER BY balance, account_number;

수정 후 결과는 실습 1의 결과 예시와 비교하세요.

3.13 · 단원 마무리

단원 마무리

WHERE로 필요한 행을 고르고 ORDER BY로 결과 순서 지정하기.

비교 조건=, <>, !=, ^=, >, >=, <, <= 사용. 문자값은 작은따옴표로 표시.
범위와 목록BETWEEN A AND B: 양 끝값 포함. IN: 목록 중 일치하는 값 선택.
문자 패턴LIKE: %는 0개 이상의 문자, _는 문자 한 개.
NULL 확인IS NULL · IS NOT NULL 사용. = NULL로 비교하지 않음.
조건 결합AND는 모두 만족, OR는 하나 이상 만족. NOT → AND → OR 순으로 해석하며 괄호로 의도를 명확히 표현.
정렬ORDER BY 컬럼 ASC / DESC. ASC는 기본값.
날짜 범위시간을 포함한 날짜는 시작 이상 · 다음 기간 시작 미만으로 지정.
SELECT 컬럼1, 컬럼2
  FROM 테이블명
 WHERE 조건
ORDER BY 컬럼1 ASC, 컬럼2 DESC;
기억할 핵심
WHERE는 행을 선택하고 ORDER BY는 표시 순서를 지정. ORDER BY가 없으면 출력 순서를 보장하지 않음.
