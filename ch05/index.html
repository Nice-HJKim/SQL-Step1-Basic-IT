5.2 · 무엇을 세는지 확인하기

무엇을 세는지 확인하기

기본 문법

COUNT(*)
COUNT(컬럼명)
COUNT(DISTINCT 컬럼명)
  • COUNT(*): 조회 대상의 전체 행 수.
  • COUNT(컬럼명): 해당 컬럼이 NULL이 아닌 행 수.
  • COUNT(DISTINCT 컬럼명): NULL과 중복을 제외한 값의 개수.

• 전체 계좌 수

SELECT COUNT(*) AS "전체 계좌 수"
  FROM accounts;

• 전체 고객 수와 연락처 등록 고객 수

SELECT COUNT(*) AS "전체 고객 수",
       COUNT(phone_number) AS "연락처 등록 고객 수"
  FROM customers;
고객 100명 중 연락처가 등록된 고객은 90명. NULL 연락처는 COUNT(phone_number)에서 제외.

• 계좌 수와 계좌 보유 고객 수

SELECT COUNT(*) AS "계좌 수",
       COUNT(DISTINCT customer_id) AS "계좌 보유 고객 수"
  FROM accounts;
계좌 수와 고객 수는 다름.
계좌는 250개, 계좌를 보유한 고객은 90명. 한 고객이 여러 계좌를 보유할 수 있음.
전체 행 개수 카운트 (NULL 포함)
COUNT(*) = COUNT(1) = COUNT(999) = COUNT('A')
  • 같은 조회 대상에서 모두 전체 행 수를 반환. 컬럼에 NULL이 있는 행도 포함.
  • 1, 999, 'A'는 NULL이 아닌 상수이므로 모든 행에서 개수를 셈.

• 계좌 수·고객 수·평균의 기준 비교

SELECT COUNT(*) AS "계좌 수",
       COUNT(DISTINCT customer_id) AS "계좌 보유 고객 수",
       ROUND(AVG(balance)) AS "계좌당 평균 잔액"
  FROM accounts;
COUNT(*)는 계좌 행 수, COUNT(DISTINCT customer_id)는 계좌 보유 고객 수.
AVG(balance)는 NULL이 아닌 계좌 잔액의 평균. 고객당 평균 잔액과 다름.
계좌를 보유하지 않은 고객은 ACCOUNTS 집계에 나타나지 않음.
5.3 · 합계·평균·최고·최저 구하기

합계·평균·최고·최저 구하기

기본 문법

SUM(숫자 컬럼)
AVG(숫자 컬럼)
MAX(컬럼명)
MIN(컬럼명)

• 최고 계좌 잔액

SELECT MAX(balance) AS "최고 잔액(원)"
  FROM accounts;

• 예금 계좌의 최고·최저·총·평균 잔액

SELECT MAX(balance) AS "최고 잔액(원)",
       MIN(balance) AS "최저 잔액(원)",
       SUM(balance) AS "총 잔액(원)",
       ROUND(AVG(balance)) AS "평균 잔액(원)"
  FROM accounts
 WHERE account_type IN ('보통예금', '정기예금');
  • SUM: 잔액의 합계.
  • AVG: 잔액의 평균. ROUND로 평균을 정수로 반올림.
  • MAX · MIN: 가장 큰 잔액과 가장 작은 잔액.
이 예제는 보통예금·정기예금 전체를 대상으로 집계.
잔액 0원도 평균 계산에 포함.
평균의 분모 확인
AVG(balance)는 잔액이 NULL이 아닌 행을 대상으로 계산.
계좌가 여러 개인 고객의 잔액이 여러 행으로 참여하므로 결과를 고객당 평균으로 부르지 않기.
ROUND(AVG(balance))는 평균을 구한 뒤 반올림. 각 잔액을 먼저 반올림한 평균과는 계산 순서가 다름.
SUM(DISTINCT balance)는 중복 계좌 제거가 아님
  • DISTINCT balance는 잔액값의 중복을 제외. 서로 다른 계좌의 잔액이 같아도 하나의 값만 합산될 수 있음.
  • 계좌의 중복 여부는 계좌번호 등 업무 키로 판단. 조인 후 중복 합산은 다음 단원에서 확인.
5.4 · NULL과 0은 다르게 계산

NULL과 0은 다르게 계산

평균을 읽을 때는 어떤 값이 계산에 포함되었는지 확인.

입력값합계평균 계산평균
100, 200, NULL300300 ÷ 2150
100, 200, 0300300 ÷ 3100
  • SUM·AVG·MAX·MIN은 NULL을 제외하고 계산.
  • 0은 값이 있으므로 평균 계산에 포함.
  • NULL을 임의로 0으로 바꾸면 평균의 의미가 달라질 수 있음.
미등록 신용점수를 0점으로 바꾸는 것은 단순 표시 변경이 아님. 집계 기준을 먼저 확인.
표현식의미100, 200, NULL일 때
AVG(값)NULL이 아닌 값의 평균150
AVG(NVL(값, 0))각 NULL을 0으로 바꾼 후 평균100
NVL(AVG(값), 0)평균 결과가 NULL일 때만 0으로 대체150
NVL의 위치가 계산 기준을 바꿈
집계 전 값 대체와 집계 후 결과 대체를 구분.
실습 잔액에 NULL이 없으면 세 식이 같은 결과일 수 있음. 위 표는 차이를 이해하기 위한 입력값 예시.

• 조회 대상 0행 · 전체 집계

SELECT COUNT(*) AS "계좌 수",
       SUM(balance) AS "총 잔액"
  FROM accounts
 WHERE 1 = 0;

• 조회 대상 0행 · 그룹별 집계

SELECT account_type,
       COUNT(*) AS "계좌 수",
       SUM(balance) AS "총 잔액"
  FROM accounts
 WHERE 1 = 0
 GROUP BY account_type;
조건결과
GROUP BY 없이 전체 집계, HAVING 없음1행 반환. COUNT는 0, SUM·AVG·MAX·MIN은 NULL
GROUP BY 있음, 조회 대상 0행그룹이 없어 결과 0행
WHERE 1 = 0은 비교를 위해 모든 행을 제외하는 조건.
값이 모두 NULL인 그룹이 실제로 존재하면 COUNT(컬럼)는 0, SUM·AVG·MAX·MIN은 NULL. COUNT(*)는 그 그룹의 행 수.
NULL과 실제 계산 결과인 0을 구분.
5.5 · GROUP BY · 종류별로 묶기

GROUP BY · 종류별로 묶기

기본 문법

SELECT 그룹 기준 컬럼, 집계 함수(컬럼명)
FROM 테이블명
GROUP BY 그룹 기준 컬럼
ORDER BY 정렬 기준;
원본 한 행계좌 한 개
→
GROUP BY계좌 종류
→
결과 한 행계좌 종류 한 개

• 계좌 종류별 계좌 수와 총 잔액

SELECT account_type AS "계좌 종류",
       COUNT(*) AS "계좌 수",
       SUM(balance) AS "총 잔액(원)"
  FROM accounts
GROUP BY account_type
ORDER BY account_type;
  • 같은 계좌 종류끼리 묶어 계좌 수와 잔액 합계를 계산.
  • 집계하지 않고 함께 출력하는 계좌 종류는 GROUP BY에 지정.
  • GROUP BY는 정렬 기능이 아님. 결과 순서는 ORDER BY로 지정.
마이너스통장의 음수 잔액도 부호 그대로 합산.
이 예제의 총 잔액은 실습 데이터의 잔액 합계임.
그룹 기준을 추가하면 결과 단위도 달라짐
GROUP BY customer_id: 고객별 한 행.
GROUP BY customer_id, account_type: 고객·계좌종류 조합별 한 행.
문법 오류를 없애기 위해 컬럼을 무조건 GROUP BY에 추가하면 업무에서 요구한 집계 단위가 바뀔 수 있음.
5.6 · WHERE · 집계할 행 선택

WHERE · 집계할 행 선택

기본 문법

SELECT 그룹 기준 컬럼, 집계 함수(컬럼명)
FROM 테이블명
WHERE 행 조건
GROUP BY 그룹 기준 컬럼
ORDER BY 정렬 기준;
  • WHERE: 집계 대상이 될 원본 행을 선택.
  • 정상 상태 계좌를 선택하고 마이너스통장은 제외.

• 정상 상태에서 마이너스통장을 제외한 계좌 종류별 집계

SELECT account_type AS "계좌 종류",
       COUNT(*) AS "계좌 수",
       SUM(balance) AS "총 잔액(원)"
  FROM accounts
 WHERE status = '정상'
  AND account_type <> '마이너스통장'
GROUP BY account_type
ORDER BY account_type;
전체 계좌의 집계와 정상 계좌만의 집계는 결과가 다름. 무엇을 집계했는지 먼저 확인.
WHERE에서 제외한 계좌는 계좌 수·합계·평균 모두에서 제외.
보고서 제목에 대상 조건을 반영. 정상 계좌 집계를 전체 계좌 집계로 해석하지 않기.
5.7 · HAVING · 집계한 그룹 선택

HAVING · 집계한 그룹 선택

기본 문법

SELECT 그룹 기준 컬럼, 집계 함수(컬럼명)
FROM 테이블명
WHERE 행 조건
GROUP BY 그룹 기준 컬럼
HAVING 집계 결과 조건
ORDER BY 정렬 기준;
구분조건의 대상예
WHERE원본 행 (Row에 대한 제한)정상 상태 계좌
HAVING집계한 그룹 (Group에 대한 제한)총 잔액이 20억원 초과

• 총 잔액이 20억원을 초과하는 계좌 종류

SELECT account_type AS "계좌 종류",
       COUNT(*) AS "계좌 수",
       SUM(balance) AS "총 잔액(원)"
  FROM accounts
 WHERE status = '정상'
  AND account_type <> '마이너스통장'
GROUP BY account_type
HAVING SUM(balance) > 2000000000
ORDER BY SUM(balance) DESC, account_type;
3개 계좌 종류를 집계한 후, 잔액 합계가 20억원을 초과하는 보통예금·정기예금 2개 그룹만 표시.
  • HAVING에서는 SUM(balance)처럼 집계식을 사용.
  • ORDER BY SUM(balance) DESC: 잔액 합계가 큰 그룹부터 표시.
  • 20억원은 조건 적용을 확인하기 위한 실습 기준.
SQL의 논리적 처리 흐름
  • FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
  • 대상 테이블 → 행 선택 → 그룹별 집계 → 그룹 선택 → 출력 항목 구성 → 정렬

• 정상 계좌의 고객별 총잔액이 1억원을 초과하는 고객

SELECT customer_id,
       COUNT(*) AS "정상 계좌 수",
       SUM(balance) AS "총 잔액"
  FROM accounts
 WHERE status = '정상'
 GROUP BY customer_id
HAVING SUM(balance) > 100000000
 ORDER BY SUM(balance) DESC, customer_id;
조건선택 기준
WHERE balance > 100000000개별 잔액이 1억원을 초과하는 계좌만 집계
HAVING SUM(balance) > 100000000고객별 잔액 합계가 1억원을 초과하는 그룹 선택
6천만원 계좌와 5천만원 계좌를 가진 고객의 합계는 1억 1천만원.
HAVING 조건에는 포함되지만, WHERE로 각 계좌에 1억원 초과를 적용하면 두 계좌 모두 제외.
논리적 처리 흐름은 결과를 이해하는 순서이며 실제 물리적 실행 순서를 뜻하지 않음.
5.8 · NULL도 하나의 그룹

NULL도 하나의 그룹

• 영업점별 고객 수

SELECT branch_id AS "영업점코드",
       COUNT(*) AS "고객 수"
  FROM customers
GROUP BY branch_id
ORDER BY branch_id NULLS LAST;
  • 같은 영업점코드의 고객을 모아 고객 수 집계.
  • 영업점코드가 NULL인 고객 10명도 하나의 그룹으로 표시.
  • NULL 그룹은 실제 영업점 하나를 의미하지 않음.
결과 11행 = 영업점코드 10개 + NULL 그룹 1개.
COUNT(DISTINCT branch_id)는 NULL을 제외하므로 10을 반환.

• NULL 그룹에서 COUNT의 기준 비교

SELECT branch_id AS "영업점코드",
       COUNT(*) AS "고객 수",
       COUNT(branch_id) AS "영업점코드 등록 수"
  FROM customers
 GROUP BY branch_id
 ORDER BY branch_id NULLS LAST;
영업점코드가 NULL인 고객 10명은 하나의 그룹.
그 그룹의 COUNT(*)는 10, COUNT(branch_id)는 0.
그룹을 만드는 기준과 COUNT가 값을 세는 기준은 서로 다름.
5.9 · 여러 기준과 월별 집계

여러 기준과 월별 집계

영업점 안에서 고객등급별 인원까지 나누어 확인하기.

영업점·고객등급별 고객 수

기본 문법

GROUP BY branch_id, customer_grade

• 영업점과 고객등급별 고객 수

SELECT branch_id AS "영업점코드",
       customer_grade AS "고객등급",
       COUNT(*) AS "고객 수"
  FROM customers
 WHERE branch_id IS NOT NULL
GROUP BY branch_id, customer_grade
ORDER BY branch_id, customer_grade;
  • 영업점코드와 고객등급의 조합이 같은 행끼리 집계.
  • 결과 한 행은 한 영업점의 한 고객등급을 의미.
  • 영업점코드가 NULL인 고객은 이 예제에서 제외.

• 2022년 개설월별 계좌 수

SELECT TRUNC(opened_date, 'MM') AS "개설월",
       COUNT(*) AS "개설 계좌 수"
  FROM accounts
 WHERE opened_date >= DATE '2022-01-01'
   AND opened_date <  DATE '2023-01-01'
 GROUP BY TRUNC(opened_date, 'MM')
 ORDER BY TRUNC(opened_date, 'MM');
결과 한 행은 한 개설월. TRUNC(opened_date, 'MM')는 월 시작일 DATE를 반환.
여러 해의 데이터를 월 숫자만으로 묶으면 서로 다른 연도의 같은 월이 합쳐질 수 있음.
해당 월에 조회 대상이 없으면 그 달의 0건 행이 자동 생성되지 않음.
연도·월별 개설 건수는 현재 잔액의 과거 월말 잔액 집계와 다름.
5.10 · GROUP BY 문법과 주의사항

GROUP BY 문법과 주의사항

기본 문법

SELECT 그룹 기준 컬럼, 집계 함수(컬럼명)
FROM 테이블명
GROUP BY 그룹 기준 컬럼;

주의사항

  • 집계하지 않고 출력하는 값은 그룹 기준으로 결정할 수 있어야 함. 기본 작성은 SELECT의 그룹 기준 컬럼·표현식과 GROUP BY를 맞추기.
  • GROUP BY 절에 있는 컬럼을 반드시 SELECT 목록에 넣을 필요는 없음.

• 예시 1. 계좌 종류와 잔액 합계를 함께 표시

SELECT account_type AS "계좌 종류",
       SUM(balance) AS "총 잔액(원)"
  FROM accounts
GROUP BY account_type
ORDER BY account_type;

• 예시 2. 계좌 종류로 묶되 잔액 합계만 표시

SELECT SUM(balance) AS "총 잔액(원)"
  FROM accounts
GROUP BY account_type
ORDER BY account_type;
그룹 기준도 함께 출력하는 방식 권장.
문법적으로 생략할 수 있지만, 어떤 계좌 종류의 합계인지 확인하려면 예시 1처럼 함께 표시.
Oracle 11g~19c의 별칭 사용
같은 SELECT 목록에서 정의한 별칭을 GROUP BY·HAVING에 사용하지 않음.
GROUP BY에는 원래 컬럼·표현식, HAVING에는 원래 집계식을 작성.
ORDER BY에서는 결과 별칭 사용 가능.
표현식과 상수
  • GROUP BY TRUNC(opened_date, 'MM')처럼 표현식으로 그룹화 가능.
  • 상수나 그룹 기준으로부터 계산할 수 있는 표현식을 출력할 수도 있음. 집계 함수가 없는 모든 표현식을 기계적으로 GROUP BY에 추가하지 않기.
5.11 · 오류 해결 퀴즈

오류 해결 퀴즈

각 SQL의 오류를 찾아 수정하고 실행 결과를 확인하세요.

• 문제 1. 영업점별 고객 수를 조회하려는 SQL

SELECT branch_id, COUNT(*) AS "고객 수"
  FROM customers;
힌트
  • 영업점별로 고객을 묶는 기준이 지정되어 있는지 확인.

• 문제 2. 총 잔액이 20억원을 초과하는 계좌 종류를 조회하려는 SQL

SELECT account_type, SUM(balance) AS "총 잔액(원)"
  FROM accounts
 WHERE SUM(balance) > 2000000000
GROUP BY account_type;
힌트
  • 원본 행에 대한 조건인지, 집계한 결과에 대한 조건인지 확인.

• 문제 3. 고객별 계좌 수를 조회하려는데 결과가 여러 행으로 나뉨

SELECT customer_id, account_number, COUNT(*) AS "계좌 수"
  FROM accounts
 GROUP BY customer_id, account_number
 ORDER BY customer_id, account_number;
힌트
  • 현재 결과 한 행은 고객 한 명인지 계좌 한 개인지 확인. SELECT와 GROUP BY를 함께 수정.

• 문제 4. 고객별 총잔액 1억원 초과 조건 검증

SELECT customer_id, SUM(balance) AS "총 잔액"
  FROM accounts
 WHERE status = '정상'
   AND balance > 100000000
 GROUP BY customer_id;
힌트
  • 개별 계좌를 고를 조건과 고객별 합계를 고를 조건을 구분.

5.13 · 단원 마무리

단원 마무리

여러 행을 집계하고 그룹별 결과에 조건 적용하기.

개수COUNT(*): 전체 행 수 · COUNT(컬럼): NULL 제외 · COUNT(DISTINCT 컬럼): NULL과 중복 제외.
합계·평균·최고·최저SUM · AVG · MAX · MIN은 NULL을 제외하고 계산. 0은 값으로 포함.
GROUP BY같은 기준값끼리 묶어 집계. 집계하지 않고 그대로 출력하는 컬럼은 GROUP BY에 포함.
WHERE · HAVINGWHERE는 원본 행에 대한 조건, HAVING은 집계한 그룹에 대한 조건.
빈 집계 결과GROUP BY·HAVING 없이 전체 집계 시 대상이 없으면 1행 반환: COUNT는 0, SUM·AVG·MAX·MIN은 NULL. GROUP BY가 있고 대상이 없으면 결과 0행.
논리적 흐름FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY.
SELECT 그룹컬럼, SUM(숫자컬럼)
  FROM 테이블명
 WHERE 행 조건
GROUP BY 그룹컬럼
HAVING SUM(숫자컬럼) > 기준값
ORDER BY SUM(숫자컬럼) DESC;
기억할 핵심
계좌 수와 고객 수는 다름. 무엇을 세는지, 결과 한 행이 무엇을 의미하는지 확인.
집계 결과 검증 체크리스트
집계 대상은 전체인지, 조건에 맞는 행만인지 확인.
결과 한 행의 업무 단위 확인.
계좌 수와 고객 수, 평균의 분모 구분.
NULL을 계산 전에 바꾸는지 결과에서 바꾸는지 확인.
WHERE와 HAVING의 조건 위치 확인.
그룹별 COUNT(*)의 합이 집계 대상 행 수와 맞는지 확인. HAVING으로 그룹을 제외한 경우는 별도 구분.
GROUP BY만으로 정렬을 기대하지 않고 ORDER BY 지정.
