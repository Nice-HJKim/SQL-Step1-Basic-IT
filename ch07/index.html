7.1 · 업무 기준을 결과로 표현하기

업무 기준을 결과로 표현하기

업무 기준을 CASE로 표현하고, 조건별 집계 결과를 검증하기.

이 장의 목표
표시와 계산 구분 → CASE 분류 → NULL 표현 선택 → 조건별 집계 → 종합 보고서 검증
업무 요청표현결과의 의미
잔액에 쉼표와 원 단위 표시TO_CHAR표시용 문자
계좌 상태·잔액 구간 분류CASE행마다 분류값
등록 연락정보 우선순위 선택COALESCENULL이 아닌 첫 값
상태별 계좌 수·잔액 합계COUNT/SUM + CASE그룹마다 조건별 숫자
SELECT의 표시·분류는 원본 값을 수정하지 않음.
CASE는 값을 반환하는 표현식. SELECT에서 분류값을 만든다고 조회 대상 행이 자동 제외되지는 않음.
날짜 변환은 Chapter 4, 집계 단위는 Chapter 5, 조인 후 행 변화는 Chapter 6과 연결.
7.2 · 금액 표시와 계산용 숫자 구분

금액 표시와 계산용 숫자 구분

기본 문법

TO_CHAR(숫자, '숫자 포맷')
포맷의미
9숫자 표시 자리
0숫자가 없는 자리도 0으로 표시
,천 단위 구분
FM채움 공백 제거

• 잔액을 천 단위 쉼표와 원 단위로 표시

SELECT account_number,
       balance,
       TO_CHAR(balance, 'FM999,999,999,999,990') || '원'
           AS "잔액 표시"
  FROM accounts
 WHERE customer_id = 1001
 ORDER BY balance DESC, account_number;
표시 자릿수 확인
  • 숫자에 비해 포맷의 자릿수가 부족하면 #으로 표시될 수 있음. 조회할 금액 범위에 맞게 자릿수 지정.

• 표시 자릿수가 부족한 경우

SELECT account_number, balance,
       TO_CHAR(balance, 'FM999,990') || '원' AS "잔액 표시"
  FROM accounts
 WHERE customer_id = 1001
ORDER BY account_number;
TO_CHAR 결과는 문자. 계산·금액 범위 조건·금액 정렬에는 원래 숫자 balance 사용.
문자 표시값을 숫자 크기 순서로 정렬한다고 기대하지 않기.
정수 포맷은 소수 금액을 표시하면서 반올림할 수 있음. 숫자 계산 결과와 표시 자릿수 구분.
음수 잔액과 최대 금액도 포맷 안에서 표시되는지 확인.
7.3 · 값에 따라 표시 문구 변경

값에 따라 표시 문구 변경

기본 문법

CASE 컬럼명
    WHEN 비교값1 THEN 결과값1
    WHEN 비교값2 THEN 결과값2
    ELSE 기본값
END
  • 단순 CASE: 컬럼의 값이 비교값과 같은지 확인.
  • ELSE: 일치하는 값이 없을 때 반환할 값.
  • END: CASE 표현식의 끝.

• 값이 같은지 비교하는 CASE

SELECT account_number, status,
       CASE status
           WHEN '정상' THEN '정상 계좌'
           WHEN '휴면' THEN '휴면 계좌'
           WHEN '해지' THEN '해지 계좌'
           ELSE '상태 확인'
       END AS "상태 표시"
  FROM accounts
ORDER BY status, account_number;
계좌 상태를 보고서용 문구로 표시.
단순 CASE는 값의 일치 여부를 비교. 범위·복합 조건·NULL 확인은 조건 CASE 사용.
CASE의 결과값은 자료형을 맞추어 작성. 숫자와 안내 문구를 한 반환값에 섞지 않기.
7.4 · 조건 순서와 경계값 검증

조건 순서와 경계값 검증

기본 문법

CASE
    WHEN 조건1 THEN 결과값1
    WHEN 조건2 THEN 결과값2
    ELSE 기본값
END

• 조건에 따라 잔액 구간 표시

SELECT account_number, balance,
       CASE
           WHEN balance IS NULL THEN '잔액 미확인'
           WHEN balance < 0 THEN '음수 잔액'
           WHEN balance = 0 THEN '잔액 없음'
           WHEN balance < 50000000 THEN '5천만원 미만'
           ELSE '5천만원 이상'
       END AS "잔액 구간"
  FROM accounts
ORDER BY balance, account_number;
위에서부터 확인하여 처음 만족한 조건의 결과를 반환.
음수 → 0원 → 5천만원 미만 → 5천만원 이상 순서로 구분.
  • NULL은 IS NULL로 확인.
  • 조건에 맞지 않고 ELSE도 없으면 NULL 반환.
  • 반환할 값은 문자끼리 또는 숫자끼리 맞추어 작성.
조건 순서 비교

• 5천만원 분기에 도달하지 못하는 조건

CASE
    WHEN balance >= 10000000 THEN '1천만원 이상'
    WHEN balance >= 50000000 THEN '5천만원 이상'
    ELSE '1천만원 미만'
END

• 큰 기준부터 검사하도록 수정

CASE
    WHEN balance IS NULL THEN '잔액 미확인'
    WHEN balance >= 50000000 THEN '5천만원 이상'
    WHEN balance >= 10000000 THEN '1천만원 이상 5천만원 미만'
    ELSE '1천만원 미만'
END
첫 SQL은 5천만원 이상도 첫 조건을 만족하므로 두 번째 분기에 도달하지 않음.
CASE는 위에서부터 처음 TRUE인 조건의 결과 반환. WHERE 조건의 실제 평가 순서와 구분.
검증 입력수정한 조건의 결과
NULL잔액 미확인
9,999,9991천만원 미만
10,000,0001천만원 이상 5천만원 미만
49,999,9991천만원 이상 5천만원 미만
50,000,0005천만원 이상
경계값이 실제 데이터에 없어도 조건의 포함·제외 기준을 대입해 검증.
이 비교는 조건식 설명용. 음수·0원을 따로 구분하는 실습 3은 별도 분기 추가.
7.5 · NULL 처리 표현 선택

NULL 처리 표현 선택

요청표현
NULL이면 대체값 반환NVL
여러 값 중 첫 등록값 선택COALESCE
NULL 여부에 따라 두 결과 중 선택NVL2
범위·복합 조건에 따라 결과 선택CASE
NVL 복습

기본 문법

NVL(확인할 값, 대체값)
  • Chapter 4에서 학습한 대체 표현. 입력값과 대체값의 자료형을 맞추고, NULL과 0의 업무 의미를 구분.

기본 문법

COALESCE(값1, 값2, 대체값)
  • 왼쪽부터 확인하여 NULL이 아닌 첫 값을 반환.
  • 모든 값이 NULL이면 NULL 반환.

• 등록된 연락정보를 우선순위에 따라 표시

SELECT customer_id, customer_name, phone_number, email,
       COALESCE(phone_number, email, '등록 정보 없음') AS "등록 연락정보"
  FROM customers
ORDER BY phone_number NULLS FIRST, customer_id;
전화번호 → 이메일 → 등록 정보 없음 순서로 표시.
NVL2 · 값의 유무에 따라 선택

기본 문법

NVL2(확인할 값, NULL이 아닐 때 결과, NULL일 때 결과)

• NVL2로 연락처 등록 여부 표시

SELECT customer_id, customer_name, phone_number,
       NVL2(phone_number, '등록', '미등록') AS "전화번호 등록 여부"
  FROM customers
ORDER BY phone_number NULLS FIRST, customer_id;
COALESCE는 왼쪽부터 NULL이 아닌 첫 값을 선택. 전화번호·이메일 우선순위를 업무 요구에 맞추기.
표시할 연락정보를 고르는 것과 실제 연락 가능 여부를 확인하는 것은 다른 작업.
7.6 · DECODE 읽고 CASE로 표현하기

DECODE 읽고 CASE로 표현하기

기본 문법

DECODE(컬럼명, 비교값1, 결과값1,
비교값2, 결과값2,
기본값)

• 기존 Oracle SQL의 DECODE 읽기

SELECT account_number, status,
       DECODE(status,
              '정상', '정상 계좌',
              '휴면', '휴면 계좌',
              '해지', '해지 계좌',
              '상태 확인') AS "상태 표시"
  FROM accounts
ORDER BY status, account_number;
범위나 여러 조건을 표현할 때는 CASE 사용.
표현NULL 확인 방법
DECODE(phone_number, NULL, '미등록', '등록')NULL 간 비교 허용 (동등 비교로 처리하여 '미등록' 반환)
CASE WHEN phone_number IS NULL THEN '미등록'
     ELSE '등록'
END
IS NULL 연산자로 정확히 판별 (표준 SQL 권장 방식)
CASE phone_number WHEN NULL THEN '미등록'
                  ELSE '등록'
END
= NULL로 비교되어 조건 미충족 (에러 없이 무조건 '등록' 반환)
기존 DECODE를 CASE로 바꿀 때 NULL 분기부터 확인.
DECODE의 NULL 일치 규칙을 일반 비교 연산자 = NULL에 적용하지 않기.
단순 값 비교는 DECODE로 읽을 수 있지만 범위·복합 조건은 CASE로 표현.
7.7 · 조건별 건수 집계

조건별 건수 집계

기본 문법

COUNT(CASE WHEN 조건 THEN 1 END)
1. CASE가 조건에 맞는 행에만 1 반환.
2. 나머지 행은 ELSE 생략으로 NULL 반환.
3. COUNT는 NULL을 제외하므로 조건에 맞는 행만 계산.

• 계좌종류별 상태별 계좌 수

SELECT account_type,
       COUNT(*) AS "전체 계좌 수",
       COUNT(CASE WHEN status = '정상' THEN 1 END)
           AS "정상 계좌 수",
       COUNT(CASE WHEN status = '휴면' THEN 1 END)
           AS "휴면 계좌 수",
       COUNT(CASE WHEN status = '해지' THEN 1 END)
           AS "해지 계좌 수"
  FROM accounts
 GROUP BY account_type
 ORDER BY account_type;
WHERE에서 정상 계좌만 먼저 선택하면 휴면·해지 계좌도 집계 대상에서 빠짐.
전체 대상은 유지하고 CASE로 각 집계에 포함할 값을 선택.
정상·휴면·해지 건수 합과 전체 계좌 수 비교. 다른 상태나 NULL이 있으면 세 건수 합이 작을 수 있음.
7.8 · 조건별 합계와 집계 오류

조건별 합계와 집계 오류

기본 문법

SUM(CASE WHEN 조건 THEN 숫자값 END)

• 전체 계좌 수를 유지하며 정상 잔액만 합산

SELECT account_type AS "계좌 종류",
       COUNT(*) AS "전체 계좌 수",
       COUNT(CASE WHEN status = '정상' THEN 1 END)
           AS "정상 계좌 수",
       SUM(CASE WHEN status = '정상' THEN balance END)
           AS "정상 계좌 총잔액(원)"
  FROM accounts
 GROUP BY account_type
 ORDER BY account_type;
조건에 맞는 잔액만 SUM의 입력값으로 전달. 나머지는 NULL.
조건에 맞는 계산값이 없거나 모두 NULL이면 SUM 결과도 NULL.
집계 결과를 0으로 대체할지는 업무 기준 확인. Chapter 5의 집계 전·후 NVL 차이와 연결.
표현식의미
COUNT(CASE WHEN 조건 THEN 1 END)조건에 맞는 행 수
SUM(CASE WHEN 조건 THEN 1 ELSE 0 END)조건에 맞는 행의 1을 더함
COUNT(CASE WHEN 조건 THEN 1 ELSE 0 END)0도 세므로 모든 행을 계산
조회 대상이 있는 그룹에서는 앞의 두 식이 같은 건수를 만들 수 있음.
대상 0행인 전체 집계에서는 COUNT는 0, SUM은 NULL. GROUP BY가 있고 대상이 없으면 결과 행 자체가 없음.
7.9 · 오류 해결 퀴즈

오류 해결 퀴즈

실행 성공 여부뿐 아니라 분류·NULL·집계 기준을 확인하고 수정하세요.

• 문제 1. 5천만원 이상 계좌가 따로 표시되지 않는 이유

SELECT account_number, balance,
       CASE
           WHEN balance >= 10000000 THEN '1천만원 이상'
           WHEN balance >= 50000000 THEN '5천만원 이상'
           ELSE '1천만원 미만'
       END AS "잔액 구간"
  FROM accounts
 ORDER BY account_number;

• 문제 2. 전화번호가 NULL이어도 등록으로 표시되는 이유

SELECT customer_id, phone_number,
       CASE phone_number
           WHEN NULL THEN '미등록'
           ELSE '등록'
       END AS "등록 여부"
  FROM customers
 ORDER BY customer_id;

• 문제 3. 정상 계좌 수가 전체 계좌 수와 같아지는 이유

SELECT account_type,
       COUNT(CASE WHEN status = '정상' THEN 1 ELSE 0 END)
           AS "정상 계좌 수"
  FROM accounts
 GROUP BY account_type
 ORDER BY account_type;
오류 원인을 설명한 뒤 수정. 조건 순서·IS NULL·COUNT의 입력값을 각각 확인.
7.10 · 업무형 실습

업무형 실습

문제와 결과를 보고 SQL을 작성하세요. 표시·분류·집계·조인을 업무 기준에 맞게 연결하세요.

실습 1. 보고서용 잔액 표시

1001번 고객의 계좌번호·계좌종류·잔액을 조회하세요. 잔액은 천 단위 쉼표와 원을 붙이고 제목을 잔액(원)으로 지정하세요. 원래 숫자 잔액 내림차순, 계좌번호 오름차순으로 정렬하세요.

실습 2. 연락정보 표시 우선순위

고객번호·고객명·등록 연락정보를 조회하세요. 이메일이 있으면 이메일, 없으면 전화번호, 둘 다 없으면 등록 정보 없음으로 표시하세요. 이메일 오름차순(NULL 먼저), 고객번호 오름차순으로 정렬하세요.

실습 3. 잔액 구간 분류

계좌번호·잔액·잔액 구간을 조회하세요. NULL은 잔액 미확인, 음수는 음수 잔액, 0원은 잔액 없음으로 표시하세요. 양수는 1천만원 미만, 1천만원 이상 5천만원 미만, 5천만원 이상으로 구분하세요. 잔액 오름차순(NULL 먼저), 계좌번호 오름차순으로 정렬하세요.

실습 4. 고객 연락정보 누락 점검

고객번호·고객명·전화번호·이메일·점검 결과를 조회하세요. 둘 다 NULL이면 연락정보 없음, 전화번호만 NULL이면 전화번호 미등록, 이메일만 NULL이면 이메일 미등록, 둘 다 있으면 모두 등록으로 표시하세요. 전화번호와 이메일 오름차순(각각 NULL 먼저), 고객번호 오름차순으로 정렬하세요.

실습 5. 계좌종류별 상태별 계좌 수

계좌종류별 전체·정상·휴면·해지 계좌 수를 한 행으로 조회하세요. 컬럼 제목은 결과 예시와 같이 지정하고 계좌종류 오름차순으로 정렬하세요.

실습 6. 계좌종류별 정상 계좌 잔액 합계

계좌종류별 전체 계좌 수·정상 계좌 수·정상 계좌 총잔액을 조회하세요. 정상 잔액을 계산할 값이 없으면 NULL을 유지하세요. 컬럼 제목은 결과 예시와 같이 지정하고 계좌종류 오름차순으로 정렬하세요.
