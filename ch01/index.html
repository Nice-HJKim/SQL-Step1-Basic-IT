생각해보기
고객 한 명이 계좌 세 개를 보유하고 있다면, 고객명과 계좌번호를 함께 조회한 결과는 몇 행일까?
해설

고객번호로 해당 계좌를 연결하고 별도 집계 없이 조회하면 3행. 고객명이 반복되어도 각 행은 서로 다른 계좌를 나타냄.

원본 테이블의 한 행과 조회 결과의 한 행은 의미가 다를 수 있음.

1.6 · 컬럼의 의미와 데이터 타입 확인

컬럼의 의미와 데이터 타입 확인

실제 컬럼타입읽어야 할 의미
ACCOUNTS.account_numberVARCHAR2(20)문자 식별자. 숫자가 포함되어도 금액처럼 계산하지 않음
ACCOUNTS.balanceNUMBER(15, 2)전체 유효 숫자 15자리, 소수 2자리. 이 정의에서 정수부 최대 13자리
ACCOUNTS.opened_dateDATE연·월·일과 시·분·초 저장 가능
TRANSACTIONS.transaction_dateTIMESTAMP날짜·시간과 소수 초 저장 가능
CUSTOMERS.phone_numberVARCHAR2(20)전화번호는 문자. NULL 허용 여부도 확인
화면에 날짜만 보인다고 시각이 없는 것은 아님.
저장 타입과 출력 형식을 구분. 날짜 조건과 변환은 이후 단원에서 실습.
  • 컬럼명뿐 아니라 업무 의미·단위·타입을 함께 확인.
  • customer_id와 branch_id가 모두 숫자여도 같은 의미의 값은 아님.
  • 테이블 구조 확인 명령과 조회 문법은 다음 단원에서 실습.
1.7 · 기본키와 제약조건 읽기

기본키와 제약조건 읽기

구분역할현재 스키마의 예
PRIMARY KEY각 행을 구분. 중복·NULL 불가ACCOUNTS.account_number
NOT NULLNULL 저장 불가ACCOUNTS.customer_id
UNIQUE같은 키 값의 중복 제한. PK와 달리 NULL 허용 가능PK의 유일성과 구분하여 이해
FOREIGN KEY참조 대상의 PK 또는 UNIQUE 키와 관계 유지ACCOUNTS.customer_id → CUSTOMERS.customer_id
DEFAULT값을 생략할 때 사용할 기본값 지정ACCOUNTS.balance DEFAULT 0

• 실제 정의에서 확인

account_number VARCHAR2(20) NOT NULL
customer_id    NUMBER(10)   NOT NULL
balance        NUMBER(15, 2) DEFAULT 0

ACCOUNTS 생성 SQL 중 컬럼 정의 발췌. 기본키·외래키는 별도의 제약조건으로 정의되어 있음.

DEFAULT 0과 NOT NULL은 다른 역할.
현재 balance는 기본값이 0이지만 NULL도 허용. 일반 DEFAULT는 명시적으로 입력한 NULL을 0으로 바꾸지 않음.
기본키는 반드시 한 컬럼일까?

여러 컬럼의 조합을 기본키로 지정할 수도 있음. 현재 주요 실습 테이블은 한 컬럼을 기본키로 사용.

1.8 · 외래키와 테이블 관계 읽기

외래키와 테이블 관계 읽기

실습 테이블의 주요 관계

화살표는 부모 → 자식 방향. 1:N은 한 부모에 여러 자식 행이 연결될 수 있다는 의미이며, 자식 행이 반드시 존재한다는 뜻은 아님. 주요 관계만 발췌.

실제 컬럼정의에서 확인할 점
ACCOUNTS.customer_idFK + NOT NULL. 계좌의 고객번호는 필수이며, 같은 고객번호가 여러 계좌에 반복될 수 있음
CUSTOMERS.branch_idFK이지만 NULL 허용. 주거래 영업점이 등록되지 않은 고객도 저장 가능
✓ FK가 있다고 모든 고객의 계좌 보유가 보장되는 것은 아님.
✓ 같은 이름의 컬럼이라고 자동으로 연결되는 것은 아님. 관계와 업무 의미를 확인하고 SQL에 연결 조건 작성.
✓ CUSTOMERS.branch_id는 고객의 주거래 영업점. 현재 ACCOUNTS에는 계좌 개설 영업점 컬럼이 없음.
왜 테이블을 나누어 저장할까?

고객 연락처를 계좌마다 반복 저장하면 변경 시 여러 행을 수정해야 함. 고객 정보는 CUSTOMERS에, 계좌 정보는 ACCOUNTS에 저장하고 고객번호로 연결.

1.10 · 구조와 관계 확인문제

구조와 관계 확인문제

1. 계좌 테이블에 같은 customer_id가 여러 번 나타나면 기본키 오류일까?

아님. ACCOUNTS의 기본키는 account_number. 한 고객의 여러 계좌는 같은 customer_id를 가질 수 있음.

2. 고객명이 같으면 같은 고객이라고 판단할 수 있을까?

판단할 수 없음. 고객번호 등 식별 기준을 확인.

3. 외래키로 지정된 컬럼에는 반드시 값이 들어 있어야 할까?

FK만으로는 NULL을 금지하지 않음. 해당 컬럼의 NOT NULL 여부를 별도로 확인.

4. DATE 컬럼이 화면에 날짜만 보이면 시각은 없다고 판단해도 될까?

판단할 수 없음. DATE는 시·분·초도 저장하며 출력 형식에 따라 보이지 않을 수 있음.

5. balance에 DEFAULT 0이 있으면 NULL은 저장될 수 없을까?

아님. 현재 balance에는 NOT NULL이 없음. 기본값과 NULL 허용 여부를 구분.

6. 고객별 계좌 현황을 작성하기 전에 무엇을 확인해야 할까?

고객별 한 행인지 계좌별 한 행인지, 계좌 없는 고객과 해지 계좌 포함 여부, 출력 항목과 정렬 기준 등을 확인.

단원 마무리

확인할 내용핵심 요약
SQL의 역할DBMS에 데이터 조회·처리 등을 요청. 업무 화면의 결과는 조건·집계·가공을 거칠 수 있음
테이블과 행고객 1명·계좌 1개·거래 1건 등 데이터 단위 확인
