6.1 · 연결할 테이블과 컬럼 찾기

흩어진 데이터를 하나로 연결하기

고객명은 고객 테이블에서, 계좌 잔액은 계좌 테이블에서 찾아 함께 확인하기.

JOIN

  • 연결 조건에 맞는 행을 찾아 여러 테이블의 정보를 함께 조회.
이 장의 목표
연결 컬럼 찾기 → INNER JOIN → OUTER JOIN
  • 같은 고객인지는 이름이 아닌 고객번호로 연결.
연결할 테이블연결 컬럼관계 (1:N)
BRANCHES ↔ CUSTOMERSbranch_id영업점 한 곳에 여러 고객
CUSTOMERS ↔ ACCOUNTScustomer_id고객 한 명이 여러 계좌 보유
CUSTOMERS ↔ LOANScustomer_id고객 한 명이 여러 대출 보유

실습용 테이블 ERD

조인 전에 정할 기준
조회 단위: 결과 한 행을 고객·계좌·거래 중 무엇으로 볼 것인가?
보존 대상: 연결 상대가 없어도 어떤 행을 유지할 것인가?
연결 관계: 상대 테이블에서 같은 키가 최대 몇 행과 연결되는가?
연결 컬럼의 의미·자료형·PK/FK·유일성을 함께 확인.
PK·FK와 조인 조건
  • FK 제약이 선언되어 있어야만 조인할 수 있는 것은 아님. 업무 관계에 맞는 조건을 직접 지정.
  • 같은 이름의 컬럼이라고 같은 의미는 아님. 복합키라면 필요한 연결 컬럼을 모두 확인. 일부만 연결하면 불필요한 조합이 생길 수 있음.
6.2 · JOIN · 연결되는 행 조회

JOIN · 연결되는 행 조회

기본 문법

ANSI 표준 조인 문법

SELECT a.컬럼명, a.컬럼명, b.컬럼명, b.컬럼명
  FROM 테이블1 a
  JOIN 테이블2 b
    ON a.연결컬럼명 = b.연결컬럼명;
  • JOIN(= INNER JOIN): 연결 조건이 일치하는 행만 조회.
  • ON: 두 테이블을 연결하는 조건 지정.

Oracle에서도 사용하는 WHERE 조인 문법

SELECT a.컬럼명, a.컬럼명, b.컬럼명, b.컬럼명
  FROM 테이블1 a, 테이블2 b
 WHERE a.연결컬럼명 = b.연결컬럼명;

• 고객의 주거래 영업점명 조회 · JOIN

SELECT c.customer_id, c.customer_name,
       c.branch_id, b.branch_name
  FROM customers c
  JOIN branches b
    ON c.branch_id = b.branch_id
ORDER BY c.customer_id;
고객 100명 중 주거래 영업점과 연결되는 90명 조회. 영업점코드가 NULL인 10명은 결과에서 제외.
JOIN은 연결 조건을 만족하는 조합을 반환. 왼쪽 행마다 결과 한 행이 보장되는 것은 아님.
이 예제는 branches.branch_id가 기본키이므로 고객 한 명당 연결되는 영업점은 최대 한 곳.
6.3 · 테이블 별칭과 WHERE 조인

테이블 별칭과 WHERE 조인

표현의미
customers c고객 테이블을 c로 짧게 표시
branches b영업점 테이블을 b로 짧게 표시
c.branch_id고객 테이블의 영업점코드
b.branch_id영업점 테이블의 영업점코드
  • 테이블 별칭은 컬럼의 출처를 구분하고 SQL을 읽기 쉽게 하는 용도.
  • Oracle에서는 테이블 별칭 앞에 AS를 붙이지 않음.
  • 양쪽에 같은 이름의 컬럼이 있으면 c.branch_id처럼 출처를 명시.

• 같은 조회를 WHERE 조인으로 작성

SELECT c.customer_id, c.customer_name,
       c.branch_id, b.branch_name
  FROM customers c, branches b
 WHERE c.branch_id = b.branch_id
ORDER BY c.customer_id;
연결 조건을 빠뜨리지 않기
  • ✓ 쉼표로 테이블을 나열한 뒤 연결 조건을 빠뜨리면 모든 행의 조합이 만들어질 수 있음.
    ⇒ 카티시안 곱(Cartesian Product, Cross Join)이 발생.
  • ✓ 고객 100명과 영업점 10곳의 모든 조합은 1,000행.
    ⇒ 불필요한 조합이 만들어지거나, 데이터가 많을수록 처리 부담도 커질 수 있음.
연결 조건 누락과 잘못된 연결 구분
조건 누락: 의도하지 않은 모든 조합이 생길 수 있음.
잘못된 컬럼 연결: SQL은 실행되어도 업무 관계와 다른 결과가 나올 수 있음.
DISTINCT를 추가하기 전에 연결 키와 결과 한 행의 의미부터 확인.
6.4 · JOIN에 조회 조건 추가

JOIN에 조회 조건 추가

기본 문법

SELECT a.컬럼명, a.컬럼명, b.컬럼명, b.컬럼명
  FROM 테이블1 a
  JOIN 테이블2 b
    ON a.연결컬럼명 = b.연결컬럼명
 WHERE 조건;

• 주거래 영업점이 연결된 VIP 고객 조회

SELECT c.customer_id, c.customer_name,
       c.branch_id, b.branch_name
  FROM customers c
  JOIN branches b
    ON c.branch_id = b.branch_id
 WHERE c.customer_grade = 'VIP'
ORDER BY c.customer_id;
  • ON: 고객과 영업점을 영업점코드로 연결.
  • WHERE: 연결된 결과에서 VIP 고객만 선택.
6.5 · 한 고객에게 여러 계좌 연결

한 고객에게 여러 계좌 연결

• 1001번 고객의 계좌 조회 · 일대다 관계

SELECT c.customer_id, c.customer_name,
       a.account_number, a.account_type, a.balance
  FROM customers c
  JOIN accounts a
    ON c.customer_id = a.customer_id
 WHERE c.customer_id = 1001
ORDER BY a.account_number;
고객 1명 × 연결된 계좌 5개 → 결과 5행.
고객번호와 고객명이 반복되어도 서로 다른 계좌를 나타내므로 정상적인 결과.
  • 결과 한 행의 의미는 계좌 한 개.
  • 한 행을 구분하는 계좌번호도 함께 확인.
  • 고객명이 반복된다는 이유만으로 DISTINCT를 적용하지 않음.
조인 후 합계를 계산할 때
  • ✓ 계좌를 거래 내역과 연결하면 같은 계좌 잔액이 거래 건수만큼 반복될 수 있음.
  • ✓ 반복된 잔액을 SUM하면 중복 합산될 수 있으므로 집계할 데이터 단위를 확인. GROUP BY만 추가해도 자동으로 해결되는 것은 아님.

• 계좌에 거래를 연결하면 잔액이 반복됨

SELECT a.account_number,
       a.balance,
       t.transaction_id,
       t.amount
  FROM accounts a
  JOIN transactions t
    ON a.account_number = t.account_number
 WHERE a.customer_id = 1001
 ORDER BY a.account_number, t.transaction_id;
결과 한 행은 연결된 거래 한 건. 같은 계좌의 잔액이 거래 건수만큼 반복됨.
반복된 a.balance를 SUM하면 같은 잔액이 여러 번 합산될 수 있음.
GROUP BY a.account_number를 추가해도 SUM의 입력값에서 반복이 자동 제거되지 않음.
SUM(DISTINCT a.balance)는 같은 잔액의 다른 계좌도 하나의 값으로 처리할 수 있어 일반적인 해결책이 아님.
계산 목적먼저 확인할 단위
계좌 잔액 합계ACCOUNTS의 계좌 한 개
거래금액 합계TRANSACTIONS의 거래 한 건
6.6 · LEFT JOIN · 연결되지 않아도 포함

LEFT JOIN · 연결되지 않아도 포함

기본 문법

LEFT OUTER JOIN

왼쪽 테이블의 모든 행과 오른쪽 테이블의 일치하는 행을 조회. 일치하는 행이 없으면 오른쪽 컬럼은 NULL로 표시.

SELECT a.컬럼명, a.컬럼명, b.컬럼명, b.컬럼명
  FROM 테이블1 a
  LEFT OUTER JOIN 테이블2 b
    ON a.연결컬럼명 = b.연결컬럼명;

RIGHT OUTER JOIN

오른쪽 테이블의 모든 행과 왼쪽 테이블의 일치하는 행을 조회. 일치하는 행이 없으면 왼쪽 컬럼은 NULL로 표시.

SELECT a.컬럼명, a.컬럼명, b.컬럼명, b.컬럼명
  FROM 테이블1 a
  RIGHT OUTER JOIN 테이블2 b
    ON a.연결컬럼명 = b.연결컬럼명;

FULL OUTER JOIN

양쪽 테이블의 일치하는 행과 연결되지 않은 행을 모두 조회. 연결되지 않은 상대 테이블의 컬럼은 NULL로 표시.

SELECT a.컬럼명, a.컬럼명, b.컬럼명, b.컬럼명
  FROM 테이블1 a
  FULL OUTER JOIN 테이블2 b
    ON a.연결컬럼명 = b.연결컬럼명;
  • LEFT JOIN: 왼쪽 테이블의 행을 유지하며 오른쪽 정보를 연결.
  • 오른쪽에 연결되는 행이 없으면 오른쪽 컬럼을 NULL로 표시.
  • LEFT OUTER JOIN과 LEFT JOIN은 같은 의미.

• 영업점 정보가 없는 고객도 포함 · LEFT JOIN

SELECT c.customer_id, c.customer_name,
       c.branch_id, b.branch_name
  FROM customers c
  LEFT JOIN branches b
    ON c.branch_id = b.branch_id
ORDER BY c.branch_id NULLS FIRST, c.customer_id;
연결 방식결과
INNER JOIN영업점이 연결되는 고객 90명
LEFT JOIN영업점 정보가 없는 고객까지 100명
LEFT JOIN은 왼쪽 행을 유지하지만 결과 행 수가 왼쪽 테이블과 같다는 뜻은 아님.
한 고객에게 계좌가 5개 연결되면 고객 정보가 반복된 5행 반환.
이후 WHERE 조건에 따라 유지되던 행이 다시 제외될 수도 있음.
6.7 · Oracle (+) 문법 읽기

Oracle (+) 문법 읽기

오라클 전용 OUTER JOIN

-- LEFT OUTER JOIN 형태
SELECT a.컬럼명, a.컬럼명, b.컬럼명, b.컬럼명
  FROM 테이블1 a, 테이블2 b
 WHERE a.연결컬럼명 = b.연결컬럼명(+);

-- RIGHT OUTER JOIN 형태
SELECT a.컬럼명, a.컬럼명, b.컬럼명, b.컬럼명
  FROM 테이블1 a, 테이블2 b
 WHERE a.연결컬럼명(+) = b.연결컬럼명;

• 같은 LEFT JOIN을 Oracle (+)로 작성

SELECT c.customer_id, c.customer_name,
       c.branch_id, b.branch_name
  FROM customers c, branches b
 WHERE c.branch_id = b.branch_id(+)
ORDER BY c.branch_id NULLS FIRST, c.customer_id;

외부 조인(Outer Join)의 작성 기준

• ANSI 표준 조인 (LEFT JOIN / RIGHT JOIN)

✓ANSI 표준 외부 조인에서는 모든 행을 빠짐없이 출력하고자 하는 기준 테이블의 위치에 따라 LEFT / RIGHT 키워드 결정.

✓가독성과 일관성을 위해 메인(기준) 테이블을 왼쪽에 두고 주로 LEFT JOIN 형태로 작성하는 것이 관례.

• 오라클 전용 문법 ((+) 연산자)

✓오라클 전용 레거시 조인에서는 짝이 없을 때 NULL로 채워져야 하는 테이블 쪽 컬럼에 (+) 기호를 붙임.

  • 같은 쿼리 블록에서 (+)와 JOIN … ON 문법을 혼용하지 않음.
  • 새 쿼리는 LEFT JOIN 중심으로 작성하고, 기존 SQL에서는 (+)의 위치를 확인.
레거시 SQL을 읽는 순서
  • (+)가 붙은 테이블과 보존할 테이블 구분.
  • 두 테이블을 연결하는 조건을 모두 확인.
  • 추가 조건의 (+) 누락으로 보존 대상이 제외되는지 확인.
  • LEFT JOIN으로 바꾸어 행 수·키·값을 비교.
  • 여러 연결 조건 중 일부에서 (+)가 빠져도 문법 오류 없이 결과만 달라질 수 있음.
6.8 · 연결되지 않은 고객 찾기

연결되지 않은 고객 찾기

• 계좌가 없는 고객도 포함

SELECT c.customer_id, c.customer_name,
       a.account_number, a.account_type, a.balance
  FROM customers c
  LEFT JOIN accounts a
    ON c.customer_id = a.customer_id
ORDER BY a.account_number NULLS FIRST, c.customer_id;
계좌 250행 + 계좌가 없는 고객 10행 = 결과 260행.

• 계좌가 없는 고객만 조회

SELECT c.customer_id, c.customer_name
  FROM customers c
  LEFT JOIN accounts a
    ON c.customer_id = a.customer_id
 WHERE a.account_number IS NULL
ORDER BY c.customer_id;
계좌의 기본키 account_number가 NULL인 결과만 선택.
기본키는 실제 계좌 행에서 NULL이 아니므로 연결 여부 확인에 사용.
NULL을 허용하는 잔액 등의 일반 컬럼으로 연결 여부를 판단하지 않음.
계좌 없음과 정상 계좌 없음은 다름
요청연결 조건과 미연결 판단
계좌 자체가 없는 고객고객번호로 계좌 연결 후 a.account_number IS NULL
정상 계좌가 없는 고객고객번호와 a.status = '정상'으로 연결 후 a.account_number IS NULL
  • 두 번째 요청은 계좌가 전혀 없는 고객과, 계좌는 있어도 정상 계좌는 없는 고객을 모두 포함. 실습 4에서 확인.
6.9 · 고객별 계좌 수 집계

고객별 계좌 수 집계

• 고객별 계좌 수 (계좌 없는 고객은 0개)

SELECT c.customer_id, c.customer_name,
       COUNT(a.account_number) AS "계좌 수"
  FROM customers c
  LEFT JOIN accounts a
    ON c.customer_id = a.customer_id
GROUP BY c.customer_id, c.customer_name
ORDER BY COUNT(a.account_number), c.customer_id;
실제 계좌번호를 세어 계좌 없는 고객은 0개로 표시.
COUNT(a.account_number)는 연결되지 않은 행의 NULL을 제외.
  • COUNT(*)는 계좌가 없는 고객의 결과 행도 1행으로 계산.
  • GROUP BY에는 고객번호와 고객명을 함께 지정.
  • 동명이인이 있어도 고객번호로 구분하여 집계.

• 조인 결과 행 수와 실제 계좌 수 비교

SELECT c.customer_id,
       c.customer_name,
       COUNT(*) AS "조인 결과 행 수",
       COUNT(a.account_number) AS "계좌 수"
  FROM customers c
  LEFT JOIN accounts a
    ON c.customer_id = a.customer_id
 GROUP BY c.customer_id, c.customer_name
 ORDER BY COUNT(a.account_number), c.customer_id;
계좌가 없는 고객반환값이유
COUNT(*)1고객을 유지한 결과 행을 셈
COUNT(a.account_number)0연결되지 않은 계좌번호 NULL은 제외
COUNT(DISTINCT c.customer_id)는 연결된 고객 수를 확인하는 용도. 계좌 잔액의 중복 합산을 해결하는 식은 아님.
6.10 · ON과 WHERE의 조건

ON과 WHERE의 조건

LEFT JOIN에서는 조건을 작성하는 위치에 따라 남는 고객이 달라질 수 있음.

• ON 절에 조건을 넣은 경우

SELECT c.customer_id, c.customer_name,
       c.branch_id, b.branch_name
  FROM customers c
  LEFT JOIN branches b
    ON c.branch_id = b.branch_id
    AND b.region_name = '대구'
ORDER BY c.customer_id;
⇒ 모든 고객을 출력하며 region_name = '대구'인 영업점만 연결.
대구가 아닌 영업점이거나 연결되는 영업점이 없으면 b.branch_id와 b.branch_name은 NULL로 표시. 고객의 c.branch_id는 원래 값 유지.

• WHERE 절에 조건을 넣은 경우

SELECT c.customer_id, c.customer_name,
       c.branch_id, b.branch_name
  FROM customers c
  LEFT JOIN branches b
    ON c.branch_id = b.branch_id
 WHERE b.region_name = '대구'
ORDER BY c.customer_id;
⇒ 이 예제에서는 LEFT JOIN으로 시작했음에도 동일한 대구 조건을 둔 INNER JOIN과 같은 결과를 반환.
조건 추가 Tip
  • LEFT JOIN의 기준 테이블 행을 모두 보존하고 싶다면: 오른쪽 테이블의 연결 대상을 제한하는 조건을 ON 절에 작성함.
  • 조인된 결과에서 특정 값만 걸러내고 싶다면: WHERE 절에 작성함. 이 예제처럼 오른쪽 컬럼에 값 비교 조건을 적용하면 INNER JOIN과 같은 효과가 생김.
추가 조건이 있는 (+) 문법

• 추가 연결 조건이 있는 (+) 읽기

SELECT c.customer_id, c.customer_name,
       c.branch_id, b.branch_name
  FROM customers c, branches b
 WHERE c.branch_id = b.branch_id(+)
    AND b.region_name(+) = '대구'
ORDER BY c.customer_id;
ON에 지역 조건을 둔 예제와 같은 결과. 전체 고객 100명 유지.
  • 이 목적에서는 b.region_name에도 (+)를 붙여 작성.
  • b.region_name = '대구'로만 작성하면 미연결 고객이 제외될 수 있음.
  • 여러 연결 조건이 있는 (+) 문장은 각 조건에 표시가 필요한지 함께 확인.
왼쪽 고객 조건도 ON과 WHERE의 의미가 다름

• ON에 VIP 조건 · 모든 고객 유지, VIP만 계좌 연결

SELECT c.customer_id, c.customer_name, c.customer_grade,
       a.account_number
  FROM customers c
  LEFT JOIN accounts a
    ON c.customer_id = a.customer_id
   AND c.customer_grade = 'VIP'
 ORDER BY c.customer_id, a.account_number;

• WHERE에 VIP 조건 · VIP 고객만 남기기

SELECT c.customer_id, c.customer_name, c.customer_grade,
       a.account_number
  FROM customers c
  LEFT JOIN accounts a
    ON c.customer_id = a.customer_id
 WHERE c.customer_grade = 'VIP'
 ORDER BY c.customer_id, a.account_number;
첫 SQL은 VIP가 아닌 고객도 남고 계좌 컬럼이 NULL로 표시.
두 번째 SQL은 VIP 고객만 남기며, VIP 고객의 미연결 행은 유지.
WHERE 조건이 있다는 이유만으로 항상 INNER JOIN과 같은 결과가 되는 것은 아님. 컬럼과 비교 조건을 함께 확인.
6.11 · 여러 테이블 연결

여러 테이블 연결

계좌에 고객명을 붙이고, 고객의 주거래 영업점명까지 연결하기.

• 계좌·고객·주거래 영업점 연결

SELECT a.account_number, c.customer_id,
       c.customer_name, b.branch_name
  FROM accounts a
  JOIN customers c
    ON a.customer_id = c.customer_id
  LEFT JOIN branches b
    ON c.branch_id = b.branch_id
ORDER BY a.account_number;
  • ACCOUNTS와 CUSTOMERS는 customer_id로 연결.
  • CUSTOMERS와 BRANCHES는 branch_id로 연결.
  • 영업점 연결에는 LEFT JOIN을 사용하여 영업점 정보가 없는 고객의 계좌도 유지.
결과의 영업점명은 계좌 소유 고객의 주거래 영업점.
현재 테이블에는 계좌 개설 영업점 컬럼이 없으므로 개설 영업점으로 해석하지 않음.
오라클 전용 조인
SELECT a.account_number, c.customer_id,
       c.customer_name, b.branch_name
  FROM accounts a, customers c, branches b
 WHERE a.customer_id = c.customer_id
   AND c.branch_id = b.branch_id(+)
ORDER BY a.account_number;

• 계좌와 대출을 고객번호로 동시에 연결하면?

한 고객의 계좌 3개

A1 · A2 · A3

한 고객의 대출 2개

L1 · L2

연결 조합 6개

A1–L1 · A1–L2
A2–L1 · A2–L2
A3–L1 · A3–L2

위 그림은 원리를 설명하기 위한 가상 개수 예시.
계좌와 대출을 고객번호만으로 동시에 연결하면 한 고객 안에서 계좌 수 × 대출 수의 조합이 생길 수 있음.
계좌 잔액은 대출 수만큼, 대출금액은 계좌 수만큼 반복.
고객별 GROUP BY를 추가해도 반복 합산은 해결되지 않음.
보충 · 각 테이블을 고객별로 집계한 뒤 연결
  • 먼저 계좌와 대출을 각각 고객별 한 행으로 요약한 뒤 연결. 괄호 안 SELECT는 집계 결과를 연결 대상으로 사용하는 인라인 뷰.
SELECT c.customer_id, c.customer_name,
       a.account_balance,
       l.loan_amount
  FROM customers c
  LEFT JOIN (
       SELECT customer_id, SUM(balance) AS account_balance
         FROM accounts
        GROUP BY customer_id
  ) a
    ON c.customer_id = a.customer_id
  LEFT JOIN (
       SELECT customer_id, SUM(loan_amount) AS loan_amount
         FROM loans
        GROUP BY customer_id
  ) l
    ON c.customer_id = l.customer_id
 ORDER BY c.customer_id;
  • 필수 실습은 중복 합산 위험과 필요한 집계 단위를 설명하는 수준. 위 쿼리는 해결 구조를 읽기 위한 보충.
  • 연결되는 집계가 없으면 합계는 NULL. 0 표시가 필요하면 업무 기준을 확인한 뒤 NVL 적용.

COUNT(*)와 COUNT(연결 키)의 의미 구분.

오류 해결 퀴즈 · 잔액 합계가 커진 이유
  • 1001번 고객의 계좌 잔액 합계를 구하려는 SQL. 거래가 여러 건인 계좌에서 어떤 일이 생기는지 설명하고, 불필요한 연결을 제거하여 수정하세요.
SELECT a.customer_id, SUM(a.balance) AS "잔액 합계"
  FROM accounts a
  JOIN transactions t
    ON a.account_number = t.account_number
 WHERE a.customer_id = 1001
 GROUP BY a.customer_id;
  • 계좌 잔액을 계산하는 데 거래 테이블이 필요한지 먼저 판단.

6.14 · 단원 마무리

단원 마무리

관계에 맞게 테이블을 연결하고 유지할 대상과 결과 단위 확인하기.

연결 컬럼이름 대신 고객번호 등 관계에 맞는 컬럼으로 연결. 별칭으로 컬럼 출처 구분.
JOIN (= INNER JOIN)연결 조건이 일치하는 행만 조회.
OUTER JOINLEFT는 왼쪽, RIGHT는 오른쪽, FULL은 양쪽의 미연결 행까지 포함. 상대 컬럼은 NULL로 표시.
Oracle (+)짝이 없을 때 NULL로 채워지는 테이블 쪽 컬럼에 표시. JOIN … ON과 같은 쿼리 블록에서 혼용하지 않음.
ON · WHEREON은 연결 조건, WHERE는 결과에서 남길 행의 조건. LEFT JOIN의 오른쪽 컬럼 조건 위치에 주의.
일대다와 집계한 고객의 여러 계좌로 행이 늘어날 수 있음. 계좌 수는 COUNT(a.account_number)로 집계.
SELECT c.customer_id, a.account_number
  FROM customers c
  LEFT JOIN accounts a
    ON c.customer_id = a.customer_id;
기억할 핵심
테이블 확인 → 연결 컬럼 찾기 → 조인 방식 결정 → 조건 위치 설정 → 결과 단위 점검.
집계까지 연결할 때
결과 한 행의 단위가 바뀌면 집계 기준도 다시 확인.
계좌가 없는 고객의 COUNT(*)는 1, COUNT(계좌번호)는 0.
정상 계좌 없음과 계좌 자체 없음은 다른 조건.
여러 일대다 테이블을 연결하면 합계가 반복될 수 있음.
계좌·대출 각각 고객별 한 행으로 요약한 후 연결하는 구조를 이해.
